嵌入式音视频相关基础知识

概述

第二个项目将在 RK3588 的基础上开发一些中间件，这一辑补充一些音视频相关的基础知识。

基础

1、视频基础

宏块 - 视频编码处理的基本单元，通常由一个 16x16 亮度像素和附加的一个 8x8 Cb 和一个 8x8 Cr 彩色像素块组成 。

I 帧 / P 帧 / B 帧 - I 帧(关键帧/帧内编码帧)是完整的独立画面，不依赖其他帧就能独立解码显示。P 帧(前向预测帧)，只记录变化部分，需要利用前面的 I 帧或 P 帧。B 帧(双向预测帧)，提供了最高的压缩比，既需要参考见面的 P 帧或 I 帧、也需要参考后面的 P 帧、I 帧。

YUV、YCbCr - 指亮度参量和色度参量分开表示的像素格式。YUV 采样和 YUV 与 RGB 之间的转换。利用了人眼对亮度敏感，对颜色不敏感的特征，将 RGB 转换成 YUV 并进行采样，扔掉一半甚至更多的色彩数据，但同时能做到压缩体积的作用。一个是为了显示(RGB)，一个是为了传输和存储(YUV)。

Profile 编码等级 - 相同画质下更复杂的算法可以大幅压缩体积。66 Baseline(只支持 I/P 帧，无交错场景)、77 Main Profile(提供 I/P/B 帧，支持无交错和交错模式)、100 High Profile。(在 Main 的基础上添加了 8x8 预测，并支持自定义量化)

QP 量化参数 - 控制量化步长。QP 每增加6，量化步长翻倍，量化步长越大意味着损失的细节越多，文件大小也越小。QP 值越小量化程度越高，画面质量越好，直接决定了码率的大小。minnqp / maxqp 编码器的最小 / 最大量化步长，分别限制最好和最差的图像质量，分别针对静止和运动画面。参数控制：QStep、MinQp、MaxQp

GOP 编码模式 - GOP(Group of Pictures) 实质就是两个 I 帧的间隔，它是一组连续的图片，是编解码器存储的基本单元。在码率不变的情况，GOP 的值越大，P、B 帧的数量就会越多，画面质量就会相对较好。可以分为普通 GOP 模式(每隔一段 GOP_SIZE 就会插入一个 I 帧)、智能编码 GOP 模式(这种模式下，分成两种I帧。一种是普通 I 帧，另外一种是虚拟 I 帧。普通 I 帧主要是检测画面的静止区域，降低码率，防止呼吸效应。在运动区域利用短期参考帧进行运动估计，并插入虚拟 I 帧)。

码率控制模式 - 码率指的是数据传输的单位时间的数据位数如 kbps。码率的设定应该大于对应分辨率的最低码率要求，小于网络带宽。
CBR(固定编码模式) 比特率在传输过程中基本上保持恒定并接近目标比特率。参数控制：u32StatTime(码率统计时间)、u32RowQpDeltaI、u32RowQpDeltaIP(行级码率控制调节幅度)
VBR(动态码率控制模式) 编码器会根据画面的复杂程度调整编码码率。简单部分较小的码率，复杂部分较高的码率。参数控制：MaxBitrate、ChangePos、MaxQp、MinQp
AVBR(平均可变码率) 属于 VBR 可变码率方式的一种，运用在静止画面和动态画面频繁切换的场景。参数控制：MaxBitrate、ChangePos、MaxQp、MinQp、MinStillPercent

2、音频基础

PCM - 脉冲编码调制数据，由模拟信号经过采样、编码等步骤转换成标准的未经过压缩的数字信号。比特率 = 采样率 * 采样深度(多少个比特位) * 通道数(单双四声道)。\

WAV - 波形音频文件，不是一种编码格式，本质是在 PCM 裸数据外面套上了一个文件头(Header)\

AAC - 高级音频编码技术，基于 MPEG-2 的一种全新音频编码技术，取代了之前的 mp3 格式。对原始的 PCM 信号进行压缩，具有更高压缩率，更高音频品质和更高的解码效率(CPU使用率更低)。有两种表现形式，ADIF(可以确定音频数据的开始位置，不需要在中间位置进行解码) 和 ADTS(每一帧都具有头部信息 = 头部信息(fixed + variable) + 裸流数据 ES)，数据结构不一样。

3、流媒体

TS 流 / PS 流 - 传输流 / 节目流，复合流的一种(一条音视频数据流中同时包含视频 ES 和音频 ES 数据)。ES 就是裸流数据(H.264 AAC)。PES，ES 无时间信息，编码器会把 ES 数据拆分成 packet 并加包头，附上 PTS(显示时间戳) 和 DTS(解码时间戳)。TS = Transport Stream + Packet Element Stream + Element Stream。

FLV - 专为网络流媒体设计的视频封装格式。由Adobe 公司推出的流媒体协议，支持的网络传输协议有限如 RTMP、HTTP-FLV。FLV = Header + Tag(video tag, audio tag, script tag)。

RTMP - 实时消息传输协议(基于 TCP 开发 把音视频数据打包成 FLV 格式)，用于音视频推流，实时交互语音和数据交互。消息协议分为三种，消息，消息块，消息分块。

协议关系 - RTP(实时传输协议 基于 UDP) RTCP(RTP 控制协议 周期性发送网络质量报告丢包率、延迟、帧同步信息 接收端接受报告后可以动态调整编码码率活 FEC 强度) RTSP(实时流传输协议 控制用 TCP 数据用 RTP 类似于遥控器 只下命令不传输视频) SIP(会话初始协议) GB/T 28181(公共安全视频监控联网系统信息传输协议 SIP + RTP)

4、编解码

H.264 - 采用了 16x16 的分块大小和对视频帧图像进行相似比较和压缩编码。视频压缩可以分为帧内压缩和帧间压缩。帧内压缩是生成 I 帧的算法，仅考虑本帧的数据，压缩率一般不高。帧间压缩则是生成 P 帧和 B 帧的算法。H.264 原始码流是编码后的基本数据流不包含任何封装信息，由 NAL 单元组成，每个 NALU 是一个基本的数据编码单元。RBSP(NAL Payload 有效负载)，提供实际编码数据，去除对解码无意义的字节填充，添加必要的终止位。VCL 和 NAL。

H.265 - HEVC，压缩率高达 1：200。采用了最小 8x8 到最大 64x64 编码宏块，在相同的分辨率下，H265 编码能够以更低的码率进行传输。一样遵循 VCL + VAL，结构上多了一个 VPS。

6、其他工具

FFmpeg - 开源、跨平台的命令行工具。格式转换(改变编码格式，调整分辨率、帧率、码率)，采集录制(从摄像头、麦克风或电脑屏幕抓取数据)，编辑处理，播放解码。

MPP - Media Process Platform(媒体处理平台)。Rockchip 为旗下芯片提供的一个底层软件库，核心目的是屏蔽不同芯片的硬件差异，提供一套统一的视频处理接口，具有视频编解码的能力。

RKNN - Rockchip Neural Network。Rockchip 为它的芯片专门打造的一套“AI 推理引擎”和“模型格式”。
