八股

概述

这是一辑 OS, Coding Language(主要是 C/C++)，Linux 驱动和应用相关的八股。可以作为扫盲和拾遗(持续连载中)。

语言(C/C++)

驱动

1. 内核模块（完结）

什么是内核？为什么要引入内核模块？内核模块的数据组织格式？ELF 文件的构成？符号导出？

内核是操作系统的核心，是基于硬件的第一层软件扩充，提供操作系统最基本的功能。Linux 采用宏内核架构，其缺点在于修改或增加内核某个功能的时候都需要重新编译一遍内核。因此引入内核模块。

内核模块就是实现了某个功能的一段内核代码，内核运行的过程中可以加载到内核中，从而动态地增加内核的功能。更专业的来说，内核模块(Loadable Kernel Module)，是一种在内核运行时加载一组目标代码来实现某个特定功能的机制。模块本身不被编译入内核镜像，这控制了内核的大小，一旦被加载它就和内核中的其他部分完全一样。

.ko 文件在数据组织上是 ELF 格式，一种普通的可重定位目标文件。起始地址处是 ELF 头部(ELF Header)，可以通过 readelf 工具查看详细的头部信息，它记录了程序头表和节区头部头表的偏移地址。节区头部表(Section Header Table)保存了不同节的基本属性结构。可以通过 readelf -S 读取节区头部的详细信息。编译器、链接器、装载器都是依靠它来定位和访问各个节的属性的。

符号指的是在内核模块中使用 EXPORT_SYMBOL 声明的函数和变量，当模块被装入内核后，所导出的符号都会记录在公关内核符号表上。如果其他模块想要利用我们模块中的符号，就可以导出。modprobe 相当于多次的 insmod，装入指定的模块及其依赖。

2. 环境搭建（完结）

驱动开发的前期准备？

设备驱动是具有独立功能的程序，可以被单独编译但无法独立运行。运行时要链接到内核作为内核的一部分在内核空间运行，因此驱动必须要在对应的内核版本上进行编译。需要知道内核版本(使用 uname -a 查看内核版本)，并准备好该版本的内核源码，使用交叉编译工具编译内核源码(准备好相关的工具)；然后依赖编译的内核源码(顶层 Makefile)编译驱动模块以及设备树文件。通过 scp 或者 NFS 工具传递给开发板。

3. 字符设备驱动（完结）

什么是字符设备？如何写一个字符设备驱动框架？读写一个设备文件背后执行的操作是什么？

字符设备是指以字节/字符来读写数据的设备，通常不支持随机存取数据，所以在实现时大多不使用缓存器(流式)。

内核将字符设备抽象成 cdev-字符设备对象，记录了设备号、操作函数集。在添加字符设备时，就是将该对象注册到内核中，通过创建一个文件 inode 绑定对象的 cdev。进程打开文件时会通过返回的 fd 创建一个 file 对象，并通过 inode 找到 cdev，将 file 的 f_op 直接指向 cdev 的 f_op。注意 inode 和 file 都能表示对文件的抽象，但 inode 是持久化的，file 则是临时的。下面是 cdev 的具体字段构成：

dev_t 数据类型表示设备号。u32数据类型，高12位是主设备号，低20位是次设备号。两种方式分配设备号：静态和动态。静态分配使用 register_chrdev_region 函数；动态分配使用 alloc_chrdev_region 函数申请设备号。使用 unregister_chrdev_region 函数释放掉设备号。

f_op 包含了一系列的函数指针，是一组标准化的调用接口，对下层进行了屏蔽，由下层具体的驱动程序来规定相应的对硬件的操作。使用 cdev_init 将 f_op 关联 cdev，cdev_add 将 cdev 加入到内核的哈希表中。

编写驱动时需要注册加载和卸载这两种函数。通过 module_init 和 module_exit 这两个入口和出口函数传参进行注册，传入具体要注册的加载和卸载函数。当使用 insmod/modprobe 命令时 init 函数会被调用。当使用 rmmod 命令时 exit 函数会被调用。

4. 设备模型（完结）

为什么要引入设备驱动模型？ /sys 记录了些什么，你可以获取什么信息，/sys 目录的作用是什么？设备驱动模型？

硬件资源如果写在驱动里，如果接口变换就需要重新修改驱动。为了避免这种耦合，Linux 引入设备驱动模型分层，将代码分成设备和驱动。设备负责提供硬件资源，驱动则负责使用这些硬件资源，并通过总线关联起来。

/sys 目录记录了各个设备之间的关系(内核导出到用户空间的)。/sys/bus 下的每个子目录都是注册好了的总线类型，每个子目录包含 devices 和 drivers 两个文件夹。devices 存放属于该总线类型的所有设备，都是符号链接指向 /sys/devices 下的真正设备。/sys/devices 是全局设备结构体系，是内核对系统中所有设备的分层次表达模型。/sys/class 包含所有注册在 kernel 里面的设备类型，按照设备功能分类的设备模型。

总线连接处理器和设备，它们依赖总线去进行通信。除了 i2c、spi 这些物理总线(它们实实在在的充当了外部输入设备和处理器的 bridge)，还存在虚拟总线(Platform)去管理那些不依赖具体物理总线的设备。总线驱动则负责实现总线的各种行为，内核把它抽象成 bus_type，管理着两个链表记录挂载在该总线上的设备和驱动，并负责他们的匹配。使用 bus_register 和 bus_unregister 来注册和注销总线，新注册的总线可以在 /sys/bus 目录下观察到。其中 match 这个函数指针必须实现，定义了总线下设备和驱动匹配的规则。

内核将设备抽象为 device，驱动抽象为 device_driver。设备含有 of_node 字段(指向 device_node)，设备树使能后，总线会将驱动的 of_match_table 以及设备树的 compatible 属性进行比较，将匹配的节点保存到该变量中。驱动成功配对设备后会执行回调函数 probe 完成设备的初始化操作，在设备从拔出时则会回调 remove。内核将 /sys 目录下的文件抽相成 attribute，我们可以读取或者修改这些属性文件进而控制我们的设备。总线、设备、驱动都包含有attribute_group这个结构体，可以利用它进行初始化避免一个一个注册 attribute。


在单片机中如果要读取某个寄存器的值可能需要加入一些新的代码并重新编译，这在 linux 下显然并不现实。linux 提供了诸如 DEVICE_ATTR 宏、device_create_file、device_remove_file(这里以 device 为例)这些 api 去快速注册和注销一个（设备）属性文件。其中 show、store 这两个函数分别对应着用户层的 cat 和 echo 命令。
你可以在 Linux 中很轻易的创建自己的虚拟总线，并在上面挂载设备和驱动。观察 /sys 目录的变化以及内核打印的日志信息，你可以清晰的理解总线是怎么管理设备和驱动的，设备和驱动如何进行匹配的，你也可以调用相关的属性文件 api 轻易地创建属于设备和驱动的属性文件，并通过 shell 对这些属性文件进行修改。

5. 平台设备驱动（完结）

第四节讨论的总线和 soc 中的物理总线概念上来说并不严格相等，对于 led、rtc 时钟、按键等不需要特殊时序的设备来说，并没有对应的物理总线，由此引入虚拟总线-平台总线(platform bus)。对应的还有 platform_device、platform_driver，它们分别继承了 device、driver。内核用 platform_bus_type 来描述平台总线，改总线在内核启动时自动进行注册。platform_match api 负责实现了平台总线和平台设备的匹配过程，平台总线提供了四种匹配方式(设备树机制、ACPI 匹配模式、id_table 方式、字符串比较)，虽然五花八门但基本上都是比较一下设备和驱动的某个成员字符串是否相同。

上图展示了平台总线匹配方式中的 id_table 的匹配机制。简单来说定义平台驱动时需要提供一个 id_table(指向platform_device_id) 的数组,该数组说明了当前驱动可以支持的设备。加载驱动时 match api 如果发现 id_table 非空的话就会去进行字符串的比较(该表和平台设备)。一旦匹配，就会把匹配的项赋值给 id_entry。
platform_device 使用结构体 resource 来抽象表示硬件信息，而软件信息可以利用设备结构体 device 中的成员 platform_data(void)进行保存。在驱动和设备匹配后，probe 的回调函数内部通常会调用 platform_get_resource，dev_get_platdata 等 api 获取平台设备提供的 resource 或软件信息。
编写并注册平台设备和驱动的基本思路：将描述硬件资源相关的信息以及寄存器偏移等软相关的信息抽象并全部塞入平台设备中，注册平台设备；驱动主要负责实现 probe 函数，完成提取资源并注册创建字符设备(以字符设备为例)。

6. 设备树

linux3.x 以后的版本引入了设备树，用来描述硬件平台的板级细节。DTS 即是所谓的设备树源文件，是一种 ASCII 文本格式的设备树描述，正如它的名字一样，硬件信息以节点的形式被树状组织起来，最顶部的根节点以”/{}”表示，一个大括号就表示了一个节点。节点可以进行相互嵌套也可以通过”&”对已有的节点进行追加内容。下面展示了节点的基本格式，其中 unit-address 需要和 reg 属性值保持一致(如果有该属性的话)，同级节点可以取相同的名字。

节点包含属性信息，这些属性信息就是要传递到内核的板级硬件描述信息。驱动中存在一些 api 用于获取这些信息。重要的属性包括 compatible, status, #address-cells, #size-cells

下面的例子展现了设备树的解析过程，以及它是如何与 Platform 总线联动的，将前面的知识点完整地串联了起来。
阶段1：dts → dtb 通过dtc编译工具编译成二进制的设备树文件 便于在内核启动时快速加载 内核接收并展开 dtb uboot 将 dtb 文件所在的内存地址传递给 Linux 内核 内核解析 dtb 文件将其中的每一个设备节点都转换成一个对应的 device_node 结构体。
阶段2：of_platform_populate函数遍历设备树中的所有节点 并由内核决定是否被创建成一个platform_device结构体。
阶段3：Platform总线驱动进行匹配与联动 driver.of_match_table和device.of_node→compatible 匹配(match函数)成功后执行probe函数 相关的硬件初始化代码。

进程：
pid和如何创建进程：pid存储在什么位置？一个直观的设计想法是存储在某一块只读内存上，我们可以通过一个指针指向这块内存读出进程号。但unix的系统设计则是pid由内核管理和记录 所以如果我们需要知道pid 就需要向OS申请 也就是通过系统调用得到pid 引出了fork execve这两个非常重要的系统调用 这当然是在unix系统下的具体实践。

进程的地址空间：mmap系统调用 将文件或者设备映射到进程的虚拟地址空间中 实现更高效的文件访问操作 假如传递的参数重fd=-1 其实就是在做匿名的内存映射 只分配内存不映射任何文件。

僵尸进程和孤儿进程：僵尸进程是说子进程退出了但是资源并没有被父进程正确地释放 僵尸进程的积累会导致内存不足 孤儿进程是说一个进程的父进程先行退出了 相关概念涉及到进程的状态转换和资源调度。

如何创建对象：通过 pipe这个系统调用可以去创建一个特殊的流式字符对象——匿名管道 这个系统调用会返回两个fd 一个指向管道的读口 一个指向管道的写口 进程同时拥有读口和写口 通过配合fork命令和fd的闪转腾挪可以实现进程之间的通信 mount命令可以创建文件系统的对象
