Linux 驱动开发中的核心机制：并发竞态、同步互斥、中断上下文与阻塞 I/O

1.并发与竞态

并发(concurreny)是指多个执行流在同一时间段内交替前进(单核 cpu)。多核 cpu 才有可能并行(parallelism)。
竞态条件(race condition)是指程序的结果依赖于多个执行流的执行顺序，而这个顺序是不确定的。

2.同步机制

同步(synchronization)是指在多个执行流之间建立正确的访问顺序和互斥关系。
三类目标：互斥(同一时间只能有一个执行流访问共享数据)、顺序(A发生后B才能继续)、条件等待(没有数据就睡眠，有数据再唤醒)

spinlock(自旋锁)

忙等，不睡眠，拿不到锁 cpu 会一直循环等待。适合临界区(访问共享资源的那段代码)极短/中断(原子)上下文。

mutex(互斥锁)

拿不到锁就睡眠，临界区代码可以睡眠。适合进程上下文，不适合用于中断处理函数。

completion

什么是completion?

一个执行流(线程)需要等待另一个执行流(线程)完成某件事(跨上下文 / 线程同步)。Linux内核为此提供了一种一次性事件同步机制。

3.同步与异步

同步调用(synchronous call)指调用者发起操作后，要等这个操作完成，才能继续向下执行。
异步调用(asynchronous call)指调用者发起操作后，不必等待任务完成，可以继续执行。任务完成后通过回调、事件、信号、队列等方式通知调用者。
同步与异步关注的是”完成通知方式”, 调用者是否要等待任务完成？ 阻塞与非阻塞关注的则是等待时是否睡眠，进程睡眠还是立即返回错误码？

4.阻塞与非阻塞

阻塞 I/O，read 是典型的阻塞行为，在没有读到数据时，当前进程会睡眠，等待数据到来在中断或其他执行流中唤醒当前进程。此行为 cpu 占用较低(内存占用多，因为一个进程实际是占据物理内存空间的)，适合简单设备和同步流程。
非阻塞 I/O，通过 O_NONBLOCK 打开设备，没有数据立即返回。此行为 cpu 占用可能较高，需要轮询或者配合 epoll 使用。适合多设备事件循环。

I/O 多路复用

让单个进程/线程能够同时监视多个文件描述符 fd ，当其中任何一个有数据可读/可写时，程序就能得到通知。

select(最早的实现)

poll(去除了 select 的最大文件描述符限制 1024)

epoll(高效设计)

5.进程上下文和中断上下文

进程上下文: 代码中出现系统调用时，陷入内核态，这时代码运行在进程上下文中。
中断上下文: 硬件事件发生，cpu 会暂停当前执行流，跳转到中断处理函数，这时代码运行在中断上下文。

6.中断上下半部

上半部 top half：真正的硬件中断处理函数
下半部 bottom half：延后执行的处理逻辑

7.总结

并发带来竞态，竞态需要同步；I/O 速度差异带来等待，等待方式形成阻塞/非阻塞；任务完成通知方式形成同步/异步；硬件事件引入中断上下文，系统调用进入进程上下文；Linux 驱动开发的核心，就是在正确的上下文中，用正确的同步机制，实现正确的 I/O 语义。
