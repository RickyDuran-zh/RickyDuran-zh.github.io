C++ 并发编程

概述

这篇博客解析 CPP 中的并发编程。

什么是并发编程？

首先区分并发(Concurrent)和并行(Parallel)的区别。并发是指在一段时间内多个任务都在推进，CPU 核心在不同线程上轮转每个线程分配固定的时间片，实际上线程运行是由先后顺序的，只不过时间片很短，看起来是这段时间内多个线程都同时在运行推进。而并行则是多个任务在同一时刻真正同时运行，比如多核 CPU 分别执行不同的任务，这是真正意义上的同时执行。
为什么需要并发？CPU 不应该因为某一个任务阻塞就让整个系统停下来。想象一个串行的程序结构，如果某一环发生阻塞，整个程序都会陷入瘫痪。并发的价值就在于把一个串行程序拆成多个相互协作的执行单元。
得益于 CPP 接近操作系统线程模型，Zero-Cost Abstraction 以及 RAII 的优势，CPP 天然非常适合这种并发编程的场景。

线程同步

并发编程的难点在于数据竞争(Data Race)，如果没有正确的线程同步可能会导致未定义行为(Undefined Behavior)。那么如何解决共享数据的问题呢？

1 Mutex

第一种工具是互斥锁(Mutex)，同一时刻只允许一个线程访问某段临界区(访问共享资源的代码段)，通过 lock() / unlock() 方法实现锁的获取和释放。通过 lock_guard、unique_lock(可以延迟上锁并自主选择上锁和解锁的时机)、scoped_lock(同时锁定 C++17 引入自动避免死锁) 这些锁管理器(Lock Guard)安全、自动地管理 Mutex 的加锁和解锁。Mutex 的经典问题是死锁(DeadLock)，也就是多个线程同时等待对方释放资源后才能继续运行，导致程序一直卡死在这，常见的解决思路是统一加锁的顺序或者使用 scoped_lock。

2 Shared Mutex

第二种工具是读写锁(Shared Mutex)。在某些场景下(数据库查询，缓存系统)出现”大量读，少量写”的需求，多个线程读取不存在什么问题，写操作需要独占。

3 Condition Variable

第三种工具是条件变量(Condition Variable)。作为线程间的通知机制，最典型的使用场景就是生产者消费者模型。为了避免忙等待(CPU 空转)使用条件变量，是一种阻塞式的同步机制。wait()实现原子性地释放锁并阻塞线程进入睡眠状态，直到被唤醒(唤醒之后还会检查条件满不满足，防止虚假唤醒)。notify_one() / notify_all() 唤醒一个或所有等待线程。另外 CV 的使用必须配合 std::unique_lock。

4 Atomic

第四种工具是原子操作(Atomic)。对于某些非常简单的共享状态，使用锁可能有点重。

5 Semaphore

第五种工具是信号量(Semaphore)。
