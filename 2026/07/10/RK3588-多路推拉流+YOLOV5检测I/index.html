RK3588-多路推拉流+YOLOV5检测I

概述

这篇博客解析项目 demo_multhread_decode_infer。

0 demo_multhread_decode_infer.cpp

这个项目的主要目标: 从 RTSP 摄像头拉取多路 H.264 流 → MPP 硬解码(解码 H.264，得到 NV12 图像数据 - YUV 的一种) → 经过回调函数转换成 BGR 图像 → NPU 跑 YOLOV5 检测 → 后处理 postprocess 画框 → 拼贴并显示在画面上。

a. 核心代码段

先确定有几路视频流，一路视频流启动一个解码线程。分别创建并运行推理线程，最后运行显示线程。一共会并行 2*N + 1 个线程。

不过为什么要取第一帧？实际上推理线程中首先也会去对 buffer 中的 img 字段进行一个拷贝，这一步操作的必要性在哪里？

b. 核心 api

load_stream - 构造 StreamLoader，设置相关参数。启动拉流解码线程。

rknn_infer - 推理线程执行的核心逻辑，判断缓冲区空不空，不空的情况下直接 clone，取解码后的帧图像，否则打印错误休眠 40 ms。调用 interf api 进行推理，把推理得到的结果再取出来。

combineImage - 拼贴帧图像并显示。

1 StreamLoader Manager & StreamLoader

这一部分需要去理解 StreamLoader 这个对象，创建并启动(open)，线程在传入 loader 后，会进入一个死循环，loop 中具体就是去执行 operator()()函数。
循环内部读帧(read_frame())，read_frame() 会调用 decode 进行解码，解码成功走回调函数 mpp_decoder_frame_callback 将 decode 后的 YUV 图像进行一个 BGR 转换，存入 buffer 中。
RTSP 传输的 H.264 数据通常是 avcc 格式（每个 NALU 前是 4 字节长度），但 MPP 解码器只支持 Annex B 格式（每个 NALU 前是 00 00 00 01 / 00 00 01 起始码）。read_frame() 通过设置比特流过滤器中间会进行一个格式的转换。
loader 线程作为 buffer 的生产者，推理线程则作为 buffer 的消费者。
StreamLoader Manager 则会去统一管理所有的 StreamLoader。

a. 仿函数(Functor)

std::thread 的构造函数要求第一个参数必须传入可调用对象。而重载 operator() 可以让一个类对象像函数一样被调用，示例如下。Functor 是一种对象，可以模仿函数的行为，可以有多种重载版本。
ref() 是一个辅助函数返回 std::reference_wrapper 类型的包装器，内部存储的是对象的引用。大概原理可能就是线程会拷贝一份包装器，但内部存储的还是对象的地址，从而达到非拷贝可以修改对象的目的。
所以引用其实是一种语法糖？本质上依然是传入地址，根据地址修改对象，而非拷贝。需要去关注 StreamLoader 在设计的时候拷贝构造是如何去进行的？

b. StreamLoader 字段和 api

**int is_annexb(const uint8_t *buf, size_t buf_size)**. Annex B 格式 以 0x000001 或 0x00000001 开头 判断是 Annex B 格式还是 AVCC 格式。
**void mpp_decoder_frame_callback(void *buffer, int width_stride, int height_stride, int width, int height, int format, int fd, void *data, int id)**. 解码后被 MPP 调用。将 YUV 数据转换成 BGR, 写入 Mbuffer, 主线程通过 queue_frame 取走。
bool StreamLoader::read_frame(). 从 RTSP 流中取一帧数据 packet，判断是不是视频包，判断是不是 Annex B 格式，decoder 进行 MPP 硬解码，解码成功后释放 packet。
int StreamLoader::open(). 设置 RTSP 连接参数，获取分辨率等参数，判断编码格式，初始化硬件编码器，注册回调函数。

3 rknn_lite

在 demo_multhread_decode_infer.cpp 中创建了 rknn_lite 实例，然后在推理线程中 clone stream_loader 的图像，并调用内部的 interf 去进行模型推理获得处理过后的图像(inference 得到原始输出 + postprocess 画框后处理)。

a. 字段

load_data 读取具体的模型传给 data 指针，load_model 调用 load_data 加载模型并通过 model_size 返回模型的大小。
在构造函数中调用 rknn_init 进行 rkModel 上下文的初始化(rknn_context 类型，代表具体的一个模型)。
接下来绑定 NPU 核心，rknn_querry 查询得到版本，设置输入输出数组(input_attrs / output_attrs)，最后配置 inputs[0]。
inputs 数组是具体的输入，其中 void* buff 字段就是用来存储具体的输入信息-图像。

b. interf() pipeline

推理线程的核心 api。首先进行 BGR->RGB 的格式转换(cv 库的默认格式和 rknn 模型的格式并不一致)，对原始图像进行压缩(符合输入的尺寸大小)，给 buff 字段进行赋值。
rknn_inputs_set 设置输入，调用 rknn_run 进行推理，rknn_outputs_get 获取 npu 的输出结果并存放在 outputs 数组中。
接着就是最最核心的调用 post_process，这个 api 是 瑞芯微官方提供的，简单来说就是对原始模型的输出进行一个后处理(使其更可读 更人性化)。把所有检测得到的框框信息存储在了detect_result_group_t detect_result_group 这个字段。最后就是通过这个字段进行画框和置信度的标注。
至于怎么进行的后处理，第三部分会对 process 和 post_process 这两个 api 进行具体的解析。

4 post_process

这一部分的作用是对 NPU 的原始输出信息进行筛选和一个后处理，直接得到有效框的坐标，对应标签和置信度，方便后续直接画框。

a. 工具 api

调用的一些工具 api。包括量化和反量化，计算 IoU， 根据置信度降序快排，nms 筛选等。
CalculateOverlap - 计算 IoU(Intersection Over Union) 交并比。两个框交集部分的面积 / 两个框并集部分的面积。

nms - Non-Maximum Suppression 非极大值抑制，把多个重叠的候选框精简成最准确的一个。把所有的框按置信度大小进行降序排列，将置信度最高的框作为候选框，和其他框计算 IoU 然后根据阈值筛掉一批重叠的框，接下来继续将置信度最高的框作为候选框重复以上的操作，剩下的都是有效框。

b. process && post_process

process - 处理数据并返回有效框的数量。三层循环，第一层是 anchor，二三层分别是行和列。可以认为原始输出的张量维度是[3,6,80,80](以输入图像 input_size = 640x640, stride = 8 为例)。这一步已经根据置信度筛掉了一大批框，将输出转化为框在图中的像素位置(left,bottom,width,height)并记录下来。

post_process - 针对大小三个不同的感受野(理解和检测不同粒度的画面)，分别跑一次 process(它们的 anchor 大小不一样，anchor数组并不一致)。针对剩下所有的框进行 nms 筛选，最后留下的就是有效框，计算出具体的坐标以及置信度，保存到结构体中，后续直接根据这个结构体绘框。
